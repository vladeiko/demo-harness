# demo-harness

Минимальный агент для программирования: языковая модель, цикл и четыре инструмента. Один файл `agent.ts`, около 210 строк, без зависимостей.

Это учебный пример. Он показывает, как генератор текста начинает читать файлы, писать код и запускать команды: модель только пишет текст с тегами `<tool_call>`, а всё остальное делает обычная программа вокруг неё.

## Что нужно

- Node.js 22.18+ или 23.6+: `.ts` запускается напрямую, без сборки.
- OpenAI-совместимый сервер с моделью. Пример написан под [llama.cpp](https://github.com/ggml-org/llama.cpp) `llama-server` и Qwen3.5 (запускай с `--jinja`). Подойдёт и Ollama, LM Studio или облачный API.

## Запуск

Перейди в папку, где агенту можно работать (лучше в пустую тестовую), и запусти:

```bash
node /путь/к/agent.ts                                  # диалог, выход: exit
node /путь/к/agent.ts "создай hello.js и запусти его"   # одна задача
```

Перед `write_file` и `run_command` агент спрашивает `[y/N]`. Он работает в текущей папке и может выполнить любую команду, на которую ты ответишь `y`.

## Настройки

Всё задаётся переменными окружения:

```bash
LLM_URL=http://192.168.1.10:8080/v1 node agent.ts   # адрес сервера, по умолчанию http://localhost:8080/v1
LOG=history.json node agent.ts                      # сохранить всю переписку с моделью
LLM_URL=https://api.example.com/v1 MODEL=<имя модели> API_KEY=<ключ> node agent.ts   # облачный API
```

## Что на экране

- серый: размышления модели (`reasoning_content`);
- голубой: сырой текст модели с тегами `<tool_call>`;
- жёлтый: что вернул инструмент (это уходит модели в `<tool_response>`);
- фиолетовый: номер шага и размер контекста в токенах;
- обычный: финальный ответ.

## Как устроен (разделы в коде)

1. **Инструменты**: `list_dir`, `read_file`, `write_file`, `run_command`, обычные функции.
2. **Системный промпт**: описание инструментов в JSON и формат вызова. Формат взят из чат-шаблона Qwen3.5 (`<tool_call><function=…><parameter=…>`), на нём модель обучали.
3. **Модель**: один `fetch` к `/chat/completions`. Параметр `tools` серверу специально не передаётся, чтобы весь механизм был виден в коде.
4. **Парсер**: две регулярки достают из текста имя функции и параметры.
5. **Цикл**: ответ модели, выполнение вызовов, результат обратно модели обычным сообщением, и так пока модель не ответит без вызовов (максимум 20 шагов).
6. **Чат** с человеком.

Ошибки модели код не прячет, а возвращает ей текстом: неизвестный инструмент, сломанный формат вызова, отказ пользователя. Если модель после вызова сама «придумала» `<tool_response>`, эта часть отрезается.

## Примеры задач

В `demo/` два маленьких проекта. Копируй их перед каждым запуском, потому что агент меняет файлы.

```bash
cp -r demo/fix-test /tmp/fix-1 && cd /tmp/fix-1 && node /путь/к/agent.ts
```

- **`demo/fix-test`**: в `cart.js` две ошибки, тесты падают. Задача: «Тесты падают. Запусти npm test, найди причину в коде и почини. Тесты не меняй. В конце убедись, что все тесты проходят.»
- **`demo/long-task`**: todo-список в командной строке. Задача: «Добавь задачам приоритет: low, medium или high, по умолчанию medium. Команда add должна принимать флаг --priority, например: node todo.js add "купить молоко" --priority high. Команда list должна сортировать задачи от high к low и показывать приоритет в строке. Добавь тесты на новое поведение, обнови подсказку по командам и проверь, что все тесты проходят.» Шагов здесь больше десяти, и маленькие модели на ней часто путаются.

## Если что-то не так

- В голубом тексте `<think>…</think>`: код его вырезает, но удобнее, чтобы llama-server отдавал размышления отдельно (`--reasoning-format deepseek`).
- Модель пишет вызов в JSON (`{"name": …}`) вместо XML: агент ответит ей «could not parse», обычно со второй попытки она исправляется.
- Посмотреть, какой текст на самом деле получает модель: запусти с `LOG=history.json`, потом `curl -s http://localhost:8080/apply-template -H "Content-Type: application/json" -d @history.json | jq -r .prompt`.
